# План реалізації ASO Screenshot Studio

Джерело вимог: [TZ.md](./TZ.md). Заплановані каталоги й межі модулів: [ASO_STRUCTURE.md](./ASO_STRUCTURE.md). План стосується вебінструмента в цьому Next.js репозиторії. Після завершення всіх етапів користувач має пройти повний шлях: створити проєкт → додати групи й слайди → зібрати композицію → локалізувати її власним OpenAI ключем → перевірити превʼю → отримати PNG або ZIP з готовими скріншотами.

## Правила виконання плану

- Етапи виконуються послідовно. Кожен закінчується доступною користувачеві функцією або завершеним вертикальним зрізом, який працює в редакторі.
- Новий інструмент живе на маршруті /aso-screenshot-studio. На головній сторінці зʼявляється перехід до нього. Наявні Wave Studio і Phone Mockup Studio продовжують працювати.
- Є одне джерело даних: версійований Project JSON. Тимчасовий стан UI — вибір, hover, відкриті модальні вікна, zoom, clipboard — не записується в проєкт. Зміни документа проходять через структуровані команди.
- Element належить Group, а не Slide. Координати зберігаються у фактичних пікселях групи. Рендер кожного слайда обрізає композицію до його області; gap ніколи не потрапляє до PNG.
- Preview і export використовують ту саму модель сцени та ті самі правила шрифтів, зображень, background і clipping. Масштаб редактора не змінює результат експорту.
- Наприкінці кожного етапу перевіряється його робочий сценарій, помилки та регресія попередніх етапів. Для чистої геометрії, серіалізації та складних операцій додаються змістовні автоматизовані тести. Build для перевірки не запускається.
- Кожна реалізована зміна отримує короткий запис у updates.md з назвою коміту у форматі type: description.

## Прийняті рішення для MVP

Ці рішення заповнюють прогалини розділу «Відкриті питання» в TZ.md, щоб план можна було виконати без прихованих блокерів.

1. Перша платформа — веб. Інтерфейс оптимізований для desktop і працює при вузькому вікні через згортання панелей та прокрутку, без обіцянки повноцінного редагування на телефоні.
2. Збереження — явний Save Project у JSON і локальне автозбереження стану документа. Користувацькі файли зберігаються окремо в IndexedDB; JSON містить лише asset references. Після імпорту на іншому пристрої відсутні файли позначаються placeholder і підставляються повторно. Якщо браузер не дає локального сховища, явний JSON export усе одно працює.
3. Бібліотека пристроїв — підготовлені 2D ракурси з описом screen mask/geometry. Кожен device element має власне посилання на screenshot. Не потрібно переносити 3D редактор Phone Mockup Studio до ASO canvas. Формат asset-маніфесту та ліцензії ресурсів фіксуються під час етапу 11.
4. Copy/paste працює між групами одного відкритого проєкту. Між різними проєктами clipboard не гарантує перенесення локальних assets; для відсутніх файлів застосовується той самий placeholder.
5. Group можна видалити з Undo. Для Project завжди доступна команда Create New Project; незбережені зміни перед заміною документа вимагають зрозумілого підтвердження.
6. Елементи з цілком однаковою площею перетину під час reorder належать слайду, де лежить їхній центр; далі — меншому поточному індексу. Для повернутих елементів MVP використовує axis-aligned bounding box, як допускає TZ.md.
7. OpenAI ключ користувача живе лише в памʼяті поточної вкладки, не зберігається в JSON, IndexedDB, localStorage або логах. UI дає змінити ключ і вибрати модель зі списку з можливістю вказати model ID. Сервер приймає ключ лише на час запиту. Список моделей перевіряється на актуальність під час реалізації.
8. Локалізація не змінює layout автоматично. Якщо одна з мов не перекладена, система показує помилку й не додає частково створені групи.
9. Перший реліз включає мінімальну практичну бібліотеку App Store / Google Play розмірів, пристроїв, фігур і декоративних assets. Значення пресетів звіряються з чинними вимогами магазинів на момент реалізації; користувач бачить точні pixel dimensions.
10. Межі памʼяті й розмірів експорту визначаються вимірюванням у браузері. При перевищенні межі показується помилка з конкретним способом зменшити завдання; експорт не повинен мовчки створювати зіпсований файл.

## Етап 1. Запуск нового інструмента на сайті

Реалізувати сторінку app/aso-screenshot-studio/page.tsx, кореневий компонент AsoScreenshotStudio, базовий layout із toolbar, лівою панеллю, workspace, Inspector і місцем для нижнього preview. Додати посилання в StudioHub і власні метадані сторінки. Задати стан порожнього редактора з кнопкою Create Project. Передбачити повернення до списку інструментів.

Результат: користувач відкриває новий маршрут із сайту й бачить самостійний інструмент, а не порожню сторінку. Інші інструменти відкриваються як раніше.

## Етап 2. Версійована модель документа і створення проєкту

У domain/schema.ts описати Project, Group, Slide, discriminated union елементів, background, padding, locale, prefix, preset і references на assets. Визначити schemaVersion, правила ID, допустимі числові межі та runtime validation для зовнішнього JSON. Відокремити serializable data від UI state. Додати createProject і команди зміни назви проєкту.

Результат: Create Project відразу відкриває workspace із валідним порожнім документом; назву можна змінити. Новий документ проходить перевірку схеми та серіалізацію без втрат.

## Етап 3. Пресети, групи й базові слайди

У domain/presets.ts завести згруповані за App Store і Google Play пресети. Реалізувати Add Group без початкового wizard: вибір платформи, розміру, locale, prefix/variant, назви та gap. Додати вибір групи, редагування цих полів, Add Slide наприкінці, видалення групи та базовий Group Inspector. Група може містити необмежену кількість слайдів; усі слайди групи мають спільні width/height.

Результат: в одному проєкті можна створити кілька вертикально розташованих груп різних розмірів і мов, додавати в них слайди та бачити їхні підписи, порядок і налаштування.

## Етап 4. Координати й спільний рендер слайдів

Реалізувати domain/geometry.ts і render/scene.ts, render/slide.ts, render/svg.ts. Для N слайдів ширина групи дорівнює N × slideWidth + (N − 1) × gap. Початок слайда i: i × (slideWidth + gap). Кожен слайд є окремою clipping region; позаслайдова зона доступна для розміщення елементів, але не експортується. Винести правила фону, clipping і порядку рендеру до спільної сцени. Додати вертикальний scroll груп та горизонтальний scroll довгих груп.

Результат: тестовий елемент може перетнути два слайди, але його частина у gap невидима. Координати не змінюються від прокрутки чи масштабу. Перевірити нуль, один і багато слайдів, а також елементи поза ними.

## Етап 5. Вибір, Inspector і базові елементи

Додати в sidebar команди створення Text, Image, Shape, Decorative Asset і Device як типів моделі; на цьому кроці достатньо простого видимого placeholder для типів, які отримають повний рендер пізніше. Реалізувати вибір group, slide, element і очищення вибору, selection frame для кожного елемента, X/Y/width/height/rotation/zIndex в Inspector. Зміна числа в Inspector негайно рухає елемент. Дати кожному типу зрозумілий початковий розмір і розташування в активній групі.

Результат: користувач додає елемент, вибирає його, змінює геометрію через Inspector і бачить синхронний результат на полотні.

## Етап 6. Маніпуляції на canvas і zoom

Реалізувати drag, resize handles і rotation control із перетворенням координат viewport → фактичні координати групи. Дозволити часткове й повне винесення елемента поза слайди. Додати preset zoom 25, 50, 75, 100, 125, 150 і 200%, з опорною точкою в центрі видимої області. Не додавати Space + Drag pan. У workspace лишається звичайна вертикальна й горизонтальна прокрутка.

Результат: елемент можна пересунути, змінити й повернути мишкою; Inspector показує точні значення. Після зміни zoom його збережені координати й майбутня роздільність експорту залишаються такими самими.

## Етап 7. Мультивибір, порядок шарів і snapping

Реалізувати multi-select із власною рамкою навколо кожного вибраного елемента. В Inspector показувати спільні властивості та mixed state; пакетне редагування застосовувати тільки до властивостей, спільних для вибраних типів. Додати Bring Forward, Send Backward, Bring to Front, Send to Back із детермінованим порядком у JSON, без повноцінної Layers panel. У domain/snapping.ts додати привʼязку до країв/центрів слайда й інших елементів, padding guides та напрямні рівних відступів. Під час руху показувати smart guides; числовий Inspector не повинен несподівано застосовувати snap.

Результат: можна одночасно пересунути й змінити спільні властивості кількох елементів; порядок накладання передбачуваний; на полотні працюють видимі напрямні.

## Етап 8. Команди, історія й клавіатура

Усі зміни документа провести через domain/commands.ts і useStudioProject. Реалізувати приблизно 10 останніх логічних кроків у useHistory: drag/resize/rotation фіксуються одним кроком після завершення жесту, а не на кожному mouse move. Додати Cmd/Ctrl+Z, Cmd/Ctrl+Shift+Z, Delete/Backspace, Cmd/Ctrl+C/V/D; paste біля курсора у валідній canvas area або поруч із джерелом, якщо курсор поза canvas. Копії отримують нові ID; device зберігає посилання на свій screenshot. Додати keyboard nudging стрілками на 1 px і Shift+стрілки на 10 px, якщо фокус не в текстовому полі. Ресурси, потрібні для Undo, не очищати до виходу відповідного кроку з історії.

Результат: усі вже наявні дії можна скасувати й повторити; копіювання, вставка й видалення працюють без втрати привʼязаних ресурсів.

## Етап 9. Текст і типографіка

Довести Text Element до всіх вимог TZ.md: content, шрифт, size, weight, italic, color, горизонтальне й вертикальне вирівнювання, line height, letter spacing, optional background/padding, wrap/no-wrap і незалежні режими width/height Auto або Fixed. Реалізувати Auto/Auto, Fixed/Auto, Fixed/Fixed з обрізанням overflow. Зберігати явні переноси рядків як структуру, відмінну від автоматичного wrap. Для rich text використовувати впорядковані сегменти зі stable ID і style overrides; редагування сегментів не повинно руйнувати ручні переноси.

Результат: один текстовий блок може мати кілька стилів, ручні переноси й передбачувані режими розміру. Текст виглядає однаково в canvas і в базовій моделі експорту.

## Етап 10. Фони й slide safe area

Додати Group Background і Slide Background з правилом: локальний slide background повністю перекриває group background. Підтримати solid, gradient, predefined image та user image, а також Stretch/Cover. Для Group Background підтримати Whole Group і Repeat Per Slide; при Whole Group координати фону спільні для всієї композиції, при Repeat Per Slide починаються заново на кожному слайді. Додати padding top/right/bottom/left для кожного слайда й linked/unlinked control. Padding показує guides і бере участь у snapping, але не обрізає вміст.

Результат: користувач змінює фон групи чи одного слайда, бачить правильний пріоритет і може задати безпечну область вручну.

## Етап 11. Користувацькі зображення, пристрої й декоративні assets

Реалізувати assetStore з ID, типом, метаданими, локальним blob, повторним використанням і коректним очищенням з урахуванням історії. У sidebar додати Uploads, базові Image, Shape і власну бібліотеку декоративних assets. Для Image визначити щонайменше position, size, rotation, opacity, fit і z-order; для Shape — вид, fill, border/radius за потреби, geometry та z-order. Підготувати кілька ліцензійно придатних 2D device variants/angles і маніфест із розмірами, screen geometry та mask. Device має власний screenshot; Upload Screenshot автоматично вписує зображення у screen mask без ручного crop/pan. Повернуті або перспективні ракурси повинні композититися однаково для editor і PNG.

Результат: користувач додає фото, фігуру й мокап, завантажує окремий screenshot до кожного device та отримує правильне накладання екрана. Дублювання device зберігає screenshot reference.

## Етап 12. Операції зі слайдами й групами

Реалізувати Insert Slide before/after, Delete Slide і Reorder Slides. Вставка посередині зміщує елементи праворуч на slideWidth + gap. Видалення видаляє весь елемент, який перетинає область видаленого слайда, і зсуває праву частину композиції вліво; Undo повертає і елементи, і ресурси. Для reorder визначати owner за найбільшою площею перетину з slide, tie-break — за центром; цілком позаслайдові елементи залишаються на місці. Slide Background рухається разом зі slide, Group Background лишається на місці. Додати Duplicate Group із новими ID для групи, слайдів та елементів і збереженням доступних asset references. Group delete також підтримує Undo.

Результат: серія слайдів і варіантів A/B редагується без втрати композиції; усі операції мають перевірені правила для елементів, що перетинають межі.

## Етап 13. Збереження, імпорт і відновлення

Реалізувати Save Project як завантаження читабельного JSON із schemaVersion і всіма serializable налаштуваннями. Open/Import Project перевіряє формат, межі та версію, показує зрозумілу помилку для пошкодженого чи непідтримуваного файлу і не стирає поточний документ при невдачі. Додати локальне автозбереження та відновлення документа; blobs користувача тримати окремо. JSON не містить base64. Якщо asset reference не розвʼязується, показати Screenshot/Image missing із Upload/Replace та зберегти інші налаштування елемента. Визначити поведінку при новому проєкті або імпорті поверх незбереженої роботи.

Результат: проєкт можна відкрити з JSON на іншому пристрої, перевʼязати відсутні images/screenshots і продовжити роботу. Перезавантаження тієї ж вкладки відновлює локально збережений документ та доступні assets.

## Етап 14. Нижня панель preview

Зробити фіксовану за висотою панель, яку можна згорнути й розгорнути. Вона показує тільки активну групу, всі її слайди в порядку й thumbnail для кожного. Регенерація через приблизно 5 секунд після останньої зміни; під час безперервного редагування лишається попередній preview. Новий запит скасовує застарілу роботу. Натискання thumbnail прокручує основний workspace до відповідного слайда.

Результат: користувач оглядає весь сет на одній панелі й переходить до потрібного слайда; інтенсивний drag не запускає рендер на кожному русі.

## Етап 15. Точний PNG і ZIP експорт

Використати спільну render model для PNG фактичного width × height кожного слайда; перед експортом дочекатися шрифтів і декодування images, включно з device composites. Реалізувати Export Slide як один PNG та Export Group як один клік без діалогу: PNG для всіх слайдів → ZIP → download. Gap не входить у жодне зображення. Назва ZIP містить project, prefix/variant, device/preset і locale; PNG мають короткі автоматичні назви з двозначним порядковим номером, без ручних назв слайдів. Забезпечити коректні символи в іменах, progress/error UI та очищення тимчасових URL/ресурсів. Перевірити великі полотна, прозорість, градієнти, fonts, rotated objects і cross-slide composition.

Результат: при будь-якому zoom одиничний PNG та PNG всередині ZIP мають задані pixel dimensions і візуально відповідають полотну/preview.

## Етап 16. Локалізація з власним OpenAI ключем

Створити модальне вікно Localize з вибором кількох target locales, зміною OpenAI ключа та вибором моделі. Ключ не зберігати в документі або браузерному сховищі. У server/prompts.ts записати англомовні промпти: це короткий ASO marketing copy для App Store/Google Play; треба зберігати сенс, тон, stable segment IDs, explicit line-break markers і не перекладати технічні ID. Передавати до сервера лише потрібні текстові сегменти та контекст, перевіряти відповідь і відповідність ID. Після успішної відповіді створювати окрему копію групи для кожної мови з новими ID, зберігаючи стилі, images, screenshots, geometry, backgrounds, порядок слайдів, prefix і variant. Замінювати лише текст. Не зменшувати шрифт і не перебудовувати layout; можливий overflow позначати для ручної перевірки. Передбачити помилки ключа, моделі, ліміту та мережі без втрати початкової групи.

Результат: із групи EN користувач за один запит отримує вибрані локалізовані групи з rich text formatting та ручними переносами, а потім окремо підлаштовує їхній дизайн.

## Етап 17. Повнота UI, доступність і крайні випадки

Довести toolbar, sidebar, group header та всі режими Inspector до переліку TZ.md: порожній вибір, Group, Slide, Text, Device, Image/Shape, Multi-selection. Додати дії Add Slide, Duplicate Group, Localize, Export, Delete Group у зрозумілі місця; на Slide — padding, фон, insert/reorder/delete/export. Передбачити стани loading, порожнього проєкту, відсутнього asset, помилки імпорту/локалізації/експорту. Перевірити клавіатурний фокус, назви кнопок, mixed state, контрастність, scroll із великою кількістю груп і слайдів та UI при вузькому desktop-вікні.

Результат: повний user flow доступний через інтерфейс без ручного редагування JSON, а помилки можна виправити, не починаючи проєкт заново.

## Етап 18. Передекспортна перевірка та завершення

Реалізувати перевірку готовності групи до експорту: знайти відсутні images/screenshots, недоступні fonts, невдалі device composites і текст, що виходить за фіксовані межі після локалізації. Показати список проблем із переходом до відповідного елемента; критичні проблеми блокують зіпсований експорт, а можливий text overflow лишається попередженням для ручного виправлення. Після цього пройти сценарій із TZ.md на реальному тестовому проєкті: створення → кілька груп і слайдів → груповий background → rich text, images, shapes і devices зі screenshots → cross-slide composition → preview → duplicate/A-B → localization кількома мовами → ручне редагування перекладу → single PNG та ZIP. Повторити після JSON export/import і після reload. Перевірити undo/redo складних операцій, збереження asset references, детермінованість назв, відсутність вмісту у gap, pixel dimensions і узгодженість preview/export. Окремо пройти регресію Wave Studio і Phone Mockup Studio. Оновити README з маршрутом, запуском і обмеженнями роботи з локальними assets; прибрати заготовки .gitkeep із непорожніх каталогів. Build не запускати; використовувати доречні локальні перевірки типів, lint, тести й ручну перевірку UI.

Результат: користувач бачить конкретні проблеми перед експортом і може перейти до їх виправлення. Усі вимоги MVP з TZ.md реалізовані й перевірені наскрізним сценарієм, а документація пояснює, як користуватися інструментом.
